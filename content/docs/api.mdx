The [OpenAPI 3.1 specification](/api/openapi) describes the request and response schemas. The examples below use `https://sonnely.com/api/sonnely/v1` as the base URL. Existing clients can also use `https://sonnely.com/v1`.

## List models

`GET /models` is public. It returns the exact model IDs, privacy tiers, and enabled provider routes with USD rates per million tokens.

```bash title="List available models"
curl https://sonnely.com/api/sonnely/v1/models
```

## Check the current API key

`GET /key` reports the authenticated key’s name, expiry, daily budget, and lifetime budget. Authenticate with the same bearer key your application uses for inference.

```bash title="Check the current API key"
curl https://sonnely.com/api/sonnely/v1/key \
  -H "Authorization: Bearer $SONNELY_API_KEY"
```

Budget values are integer micro-USD. Each budget includes `cap_microusd`, `used_microusd`, and `remaining_microusd`. An unlimited cap and its remaining amount are `null`. The daily budget includes `resets_at` at the next midnight UTC. `expires_at_ms` is a Unix timestamp in milliseconds or `null` for keys without expiry. Usage includes settled charges and active reservations.

## Provider catalogs

[GET /provider-models](/api/sonnely/v1/provider-models) returns full upstream inventories, including entries that Sonnely lists for discovery. Use the configured provider list and endpoint mappings to check whether Sonnely can run a model.

## Specialized inference

`POST /embeddings`, `POST /rerank`, image generation and edits, System One, redaction, document conversion, Responses, and the audio endpoints use the same Sonnely API key and credit controls as Chat Completions. [Realtime and additional Tinfoil endpoints](/docs/providers#additional-tinfoil-endpoints) describe their request formats. Choose an endpoint in the [Playground](/console) to try these operations with your signed-in workspace credits. See [model IDs and accepted request fields](/docs/providers#embeddings-decisions-images-and-audio).

## Create a completion

`POST /chat/completions` returns a Chat Completion or a server-sent event stream. Create a key in the [console](/console/keys) and export it as `SONNELY_API_KEY` before running the example.

```bash title="Send a text completion"
curl https://sonnely.com/api/sonnely/v1/chat/completions \
  -H "Authorization: Bearer $SONNELY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-ai/DeepSeek-V4.1-Flash-1017",
    "messages": [{"role": "user", "content": "Summarize this request in one sentence."}],
    "max_tokens": 64
  }'
```

## Completion fields

| Field                          | Behavior                                                                |
| ------------------------------ | ----------------------------------------------------------------------- |
| `model`                        | Required. Use the exact public ID from `/models`.                       |
| `messages`                     | Required. Text-only objects with `role` and `content`.                  |
| `max_tokens`                   | Optional output allowance. Defaults to 512.                             |
| `provider.only`                | Optional array containing exactly one route ID advertised by `/models`. |
| `max_cost_microusd`            | Optional positive integer ceiling on the credit reservation.            |
| `stream`                       | Set to `true` to receive [SSE](/docs/streaming).                        |
| `stream_options.include_usage` | Set to `true` to include settled usage in the stream.                   |

Send `Content-Type: application/json`. Add `X-Sonnely-Receipt: v1` to receive the [completion receipt](/docs/attestation#completion-receipts).

## Chat Completions limits

The gateway accepts up to 36,000 bytes of JSON, up to 32 messages with roles `system`, `user`, or `assistant`, and up to 12,000 characters per message. `max_tokens` accepts integers from 1 to 2,048.

Use the fields listed above and the features advertised on the selected provider route. For audio, documents, embeddings, and the Responses API, use the [specialized endpoints](#specialized-inference). See [errors and recovery](/docs/troubleshooting) for HTTP and stream failures.

## Request references and retries

For programmatic retries, send an `Idempotency-Key` header unique to the operation. Use the same value if the connection drops. A repeat returns HTTP 409 with the original `X-Sonnely-Request-Id` and does not reserve credits again. Paste that reference into [Request logs](/console/logs) to check settlement. Completion bodies are not stored for replay.

## Tool calling and structured output

Check the `capabilities` object on the exact route in `GET /v1/models`. When `tools` is true, you can send OpenAI-style function definitions, consume `tool_calls`, then send the results as `tool` messages. Your client runs the tools. When `structured_outputs` is true, you can request `response_format` with a JSON object or a JSON schema. Sonnely preserves provider streaming usage and settles the request using reported tokens.
