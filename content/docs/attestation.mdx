## Data handling

Requests travel over HTTPS to the Sonnely gateway, which reads the prompt to validate and forward the request.

> **Gateway boundary.** The Sonnely gateway is outside the trusted execution environment that runs the model.

Sonnely’s ledger records account, model, token, status and charge metadata. Optional chat history lives in the browser and can be cleared in [Settings](/console/settings). See the [Privacy Notice](/privacy) for details.

## Evidence

Every route executes inside a trusted execution environment and supplies evidence describing that environment. The optional completion receipt records which checks passed for a given request so you can verify the attestation before relying on a specific hardware or software claim.

## Completion receipts

Send `X-Sonnely-Receipt: v1` to include `sonnely_receipt` in the response. A receipt records the route, requested model, completion ID, billing reference, charge in millionths of a dollar, and SHA-256 hashes of the request and response exchanged upstream.

> **Keep receipts private.** The hashes can confirm guesses about their contents.

- `signature_matched` identifies a match between the upstream payload and its declared signing address.
- `aci_payload_matched` identifies a matched attestation payload and route.
- `attested_router` identifies a verified router release.

Use the receipt schema for field definitions and other statuses. The evidence fields present depend on the route that carried the request. [Contact us](/contact) if you need verification guidance for a specific route.
