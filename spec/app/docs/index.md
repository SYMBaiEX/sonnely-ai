# Docs

The guides and reference the product ships with. Every page under `/docs` is
a guide in the catalog: the sidebar, the previous and next links, the in-page
search, the `/api/search` endpoint and the markdown feeds (`/llms.txt`,
`/llms-full.txt` and each page's `content.md`) all read the same list.

## Domain

### A doc is a page of the documentation

A doc names its route slug, its title and description, and the sidebar
section it sits in ("" for the overview at `/docs`); `bodies` lists its body,
parallel to the catalog, as a list of markdown lines. Lines starting with `@` mark the structures
a markdown body cannot:
`@steps`/`@step`, `@tabs`/`@tab`, `@box` (facts, procedure, sequence, next,
overview, start, guidegrid, support), `@group`/`@link`, `@card` and `@apiref`.
Quint strings hold no escapes, so a body writes `§` for a backslash and `‖`
for a double quote, neither of which appears in the content; the shell
decodes them before the lines are rendered or served.

```quint
type Doc = { slug: str, title: str, description: str, section: str }
```

### The catalog lists every guide in sidebar order

The overview leads, then the guides of each section in `meta.json` order.
`apiEndpoints` is the endpoint table the API reference opens with.

### The docs a slug names are found in the catalog

`docAt` answers the first doc with a slug, or the empty doc when none
matches; `bodyAt` gives its markdown lines. `prevSlugs` and `nextSlugs` name
the previous and next guides in catalog order, and `slugBefore` and
`slugAfter` read them for a slug, answering "" for a slug the catalog does
not hold and at the ends.

```quint
pure val emptyDoc: Doc = { slug: "", title: "", description: "", section: "" }

pure val emptyEndpoint: Endpoint = { method: "", path: "", anchor: "", description: "" }

pure def isDoc(slug: str): bool = docs.listMap((d) => d.slug).includes(slug)

pure def docAt(slug: str): Doc =
  docs.foldl(emptyDoc, (found, d) => if (d.slug == slug) d else found)

type DocCursor = { i: int, found: int }

pure def indexOf(slug: str): int =
  val start: DocCursor = { i: 0, found: -1 }
  docs.foldl(start, (acc, d) =>
    if (acc.found >= 0) acc
    else if (d.slug == slug) { i: acc.i, found: acc.i }
    else { i: acc.i + 1, found: -1 }
  ).found

pure def bodyAt(slug: str): List[str] = bodies.nthOr(indexOf(slug), List())

pure def slugBefore(slug: str): str = prevSlugs.nthOr(indexOf(slug), "")

pure def slugAfter(slug: str): str = nextSlugs.nthOr(indexOf(slug), "")

pure def docsIn(section: str): List[Doc] =
  docs.foldl(List(), (listed, d) => if (d.section == section) listed.concat(List(d)) else listed)

pure val lastDoc: Doc = docs.nthOr(docs.length() - 1, emptyDoc)

pure val iValues = Set(-1, 0, 1, 5, 8, 13, 14, 15)

pure val jValues = Set(-1, 0, 1, 6, 13, 14, 15)

pure val kValues = Set(-1, 0, 1, 2, 3, 4, 5)
```

## Story: Read the documentation

> As a visitor, I want to browse the sidebar and open a guide, so that I can
> learn the product at my own pace.

The sidebar shows the overview and one group per section in catalog order;
opening a guide shows its page. The in-page search and `/api/search` answer
with docs from the same catalog.

### Every guide is listed once

Each slug appears once in the catalog, so `/docs/<slug>` names one guide and
each markdown feed can publish it under that name.

```quint
pure def lawSlugListedOnce(i: int, j: int): bool =
  (0 <= i and i < j and j < docs.length()) implies
    docs.nthOr(i, emptyDoc).slug != docs.nthOr(j, emptyDoc).slug
```

### The sidebar leads with the overview

```quint
pure def lawOverviewFirst(i: int): bool =
  (0 <= i and i < docs.length()) implies
    ((docs.nthOr(i, emptyDoc).section == "") iff docs.nthOr(i, emptyDoc).slug == "index")
```

### Every guide sits in a named section

The overview alone carries no section; every other guide names one of the
sidebar's sections.

```quint
pure def lawDocSection(i: int): bool =
  (0 <= i and i < docs.length()) implies
    (docs.nthOr(i, emptyDoc).section == "" or
     sections.includes(docs.nthOr(i, emptyDoc).section))
```

### Each section lists its guides

`sectionFirst` names the catalog index of each section's first guide, and
that guide names the section.

```quint
pure def lawEachSectionListsGuides(k: int): bool =
  (0 <= k and k < sections.length()) implies
    docs.nthOr(sectionFirst.nthOr(k, -1), emptyDoc).section == sections.nthOr(k, "")
```

### A guide is found by its slug

```quint
pure def lawDocAtFinds(i: int): bool =
  (0 <= i and i < docs.length()) implies
    docAt(docs.nthOr(i, emptyDoc).slug) == docs.nthOr(i, emptyDoc)
```

## Story: Move between guides

> As a reader, I want to step to the previous or next guide from the bottom of
> a page, so that I can read the documentation in order.

The page footer offers previous and next in catalog order; neither end of the
catalog offers a step past it.

### Previous and next follow the catalog order

Stepping back then forward, or forward then back, returns to the same guide.

```quint
pure def lawBeforeAfterRoundTrip(i: int): bool =
  (0 <= i and i < docs.length()) implies
    (i == 0 or nextSlugs.nthOr(i - 1, "") == docs.nthOr(i, emptyDoc).slug)

pure def lawAfterBeforeRoundTrip(i: int): bool =
  (0 <= i and i < docs.length()) implies
    (i == docs.length() - 1 or prevSlugs.nthOr(i + 1, "") == docs.nthOr(i, emptyDoc).slug)
```

### The ends of the catalog have no neighbour

```quint
pure def lawEndsOfTheCatalog(i: int): bool =
  (0 <= i and i < docs.length()) implies
    ((prevSlugs.nthOr(i, "") == "") iff i == 0) and
    ((nextSlugs.nthOr(i, "") == "") iff i == docs.length() - 1)
```

### A guide's neighbours are guides

```quint
pure def lawNeighborsAreDocs(i: int): bool =
  (0 <= i and i < docs.length()) implies
    (i == 0 or prevSlugs.nthOr(i, "") == docs.nthOr(i - 1, emptyDoc).slug) and
    (i == docs.length() - 1 or nextSlugs.nthOr(i, "") == docs.nthOr(i + 1, emptyDoc).slug)
```

## Story: Serve the documentation as markdown

> As a tool, I want the same documentation as markdown, so that language
> models and agents can read every guide without the rendered page.

`/llms.txt` indexes the whole catalog, `/llms-full.txt` concatenates it, and
each guide is also served at `content.md` under its slug.

### The catalog holds the guides the product ships

The overview plus the guides of the three sections: fifteen pages, the full
set the documentation site serves.

```quint
pure def lawCatalogIsComplete(i: int): bool =
  (0 <= i and i < docs.length()) implies docs.length() == 15
```

### Every doc a feed serves is readable

Each page's markdown feed and index line can be written from its title,
description and body, so none of them is empty.

```quint
pure def lawDocContent(i: int): bool =
  (0 <= i and i < docs.length()) implies
    (docs.nthOr(i, emptyDoc).title != "" and
     docs.nthOr(i, emptyDoc).description != "" and
     bodies.nthOr(i, List()).length() > 0)
```

### Every endpoint the reference lists is documented

Each row of the endpoint table names its method, its path and what it does.

```quint
pure def lawEndpointsAreDocumented(i: int): bool =
  (0 <= i and i < apiEndpoints.length()) implies
    (apiEndpoints.nthOr(i, emptyEndpoint).method != "" and
     apiEndpoints.nthOr(i, emptyEndpoint).path != "" and
     apiEndpoints.nthOr(i, emptyEndpoint).description != "")
```
