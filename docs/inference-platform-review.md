# Inference platform review

Reviewed November 24, 2026. The benchmark covers general-purpose gateways, direct inference platforms, and private inference services. The comparison uses public product and API documentation together with Sonnely’s console, gateway contracts, and ledger.

## Customer workflows

| Workflow | Benchmark | Sonnely and the gap addressed |
| --- | --- | --- |
| Debug one request | OpenRouter Activity and Logs support searching generations and drilling into billing, timing, and attempts. Vercel AI Gateway shows request and provider-attempt details. [OpenRouter Logs](https://openrouter.ai/docs/guides/features/logs) · [Vercel Gateway Logs](https://vercel.com/changelog/ai-gateway-logs) | Sonnely already recorded requests and operator traces. The customer request log brings account-scoped lookup, filtered history, timing and billing detail, and CSV export of loaded rows into the workspace. |
| Understand usage | Cloudflare and Portkey segment request metrics by provider, model, and metadata. Privatemode exposes token usage by model and workload. [Cloudflare Analytics](https://developers.cloudflare.com/ai-gateway/observability/analytics/) · [Portkey Filters](https://portkey.ai/docs/product/observability/filters) · [Privatemode Usage](https://docs.privatemode.ai/portal/usage/) | Sonnely already had live totals, daily charts, and simple model and key grouping. The usage dashboard work adds shared filters, provider breakdowns, sorting, observed timing and cache metrics, and clearly scoped exports. |
| Choose and use a model | Replicate publishes model-specific input schemas and Fireworks links models to playgrounds. [Replicate HTTP API](https://replicate.com/docs/reference/http) · [Fireworks Model Library](https://fireworks.ai/models) | Sonnely’s catalog already covered all routed and discovery entries. Model cards expose the exact provider route, gateway support, price units, and request examples for each listing. |
| Diagnose a key or integration | OpenRouter returns information about the bearer key itself. OpenAI SDKs expose request IDs and structured HTTP errors. [OpenRouter current key API](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-key) · [OpenAI Python SDK](https://github.com/openai/openai-python#request-ids) | Sonnely already enforced daily and lifetime key budgets and emitted request references and idempotency conflicts. The integration work surfaces these details to authenticated API clients. |

## Broader platform gaps

| Area | Sonnely release | Remaining work and benchmark |
| --- | --- | --- |
| Private routing and failover | Chat Completions supports explicit, ordered, same-model failover across eligible Private TEE routes. A single reservation covers the most expensive eligible route, and Request logs show each attempt. [Private routing guide](https://sonnely.com/docs/api#private-routing-and-failover) | Workspace policies, health-based ordering, and fallback for additional endpoints would extend the current per-request controls. [OpenRouter Provider Selection](https://openrouter.ai/docs/guides/routing/provider-selection) · [Cloudflare Dynamic Routing](https://developers.cloudflare.com/ai-gateway/features/routing/) |
| Teams, projects, and budgets | Teams use wallet-bound invitations and owner, admin, and member roles. Owner-funded projects have scoped keys, lifetime budgets, and their own recent request activity. [Teams guide](https://sonnely.com/docs/teams) | Shared funding, organization identity and provisioning, and configurable team-wide routing policies remain separate work. [OpenRouter Workspaces](https://openrouter.ai/docs/guides/features/workspaces/overview) · [Privatemode Organizations](https://docs.privatemode.ai/portal/organizations/) · [Vercel Budgets](https://vercel.com/docs/ai-gateway/observability-and-spend/budgets) |
| Customer verification | The browser receipt inspector parses completion evidence, checks supported NEAR signatures against their declared signer, and compares optional local files with the recorded digests. [Receipt inspector](https://sonnely.com/verify) | End-to-end encrypted routing requires a separate client protocol and billing design. Independent provider attestation still depends on the provider’s evidence and verification steps. [Tinfoil Verification Center](https://docs.tinfoil.sh/guides/verification-center) · [Tinfoil Proxy Server](https://docs.tinfoil.sh/guides/proxy-server) · [NEAR Model Attestations](https://docs.near.ai/cloud/verification/cloud-api/model-attestations) |
| Batch inference and asynchronous jobs | Batch preflights JSONL and runs nonstreaming Chat Completions at standard inference rates. The browser holds files, checkpoints, and results, with pause, resume, and JSONL exports. [Batch guide](https://sonnely.com/docs/batch) | Hosted asynchronous jobs would need explicit retention, cancellation, concurrency, and partial-failure settlement. [OpenAI Batch](https://developers.openai.com/api/docs/guides/batch) · [Groq Batch](https://console.groq.com/docs/batch) · [Together Batch](https://docs.together.ai/docs/inference/batch/overview) · [Replicate Data Retention](https://replicate.com/docs/topics/predictions/data-retention) · [Fireworks Batch Migration](https://docs.fireworks.ai/guides/batch-migration) |

Sonnely’s provider catalogs describe upstream capabilities. Gateway compatibility depends on the specific Sonnely route. A wider catalog, hosted processing, or automatic fallback should be evaluated on its behavior and privacy boundary as well as whether another platform offers it.
